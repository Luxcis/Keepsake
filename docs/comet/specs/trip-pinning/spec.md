# 旅行置顶

## 能力说明

管理端旅行管理支持将任意一个旅行设为置顶。置顶是旅行记录上的单值标记：同一时刻最多只有一个旅行处于置顶状态，将新旅行设为置顶时原置顶自动取消。置顶与发布状态相互独立，草稿旅行也能被置顶，但只有已发布的置顶旅行会在前台生效。

已发布的置顶旅行从足迹卡片列表移除，改为在时光轴最顶部单独展示，该节点不显示日期，不加额外标识。公开旅行列表接口在每条已发布旅行上返回布尔字段 `pinned`，前台各页面据此决定展示方式，不新增额外请求。

取消置顶或删除置顶旅行后，该旅行回到原有日期排序位置；页面不保留空的置顶节点，也不会因此报错。

## Requirement: 管理端置顶入口

- **WHEN** 管理员打开旅行管理列表
- **THEN** 每个旅行行内显示「置顶」或「取消置顶」按钮
- **AND** 已置顶的旅行行内显示已置顶标识；草稿被置顶时标识同时说明「发布后生效」
- **AND** 旅行编辑表单只读显示当前置顶状态，不提供第二个置顶开关

## Requirement: 唯一置顶

- **WHEN** 管理员将某个旅行设为置顶
- **THEN** 该旅行变为置顶，之前被置顶的旅行自动取消置顶
- **AND** 再次点击同一旅行的「取消置顶」后，没有任何旅行处于置顶状态
- **AND** 数据库层面的约束保证不会同时存在两个置顶旅行

## Requirement: 置顶与发布状态

- **WHEN** 草稿旅行被置顶
- **THEN** 置顶标记保留，管理端显示「发布后生效」
- **AND** 该旅行发布后，置顶立即在足迹列表与时光轴生效
- **AND** 已置顶的旅行改为草稿后，前台不再展示其置顶节点

## Requirement: 置顶接口

- **WHEN** 管理员向 `PUT /api/admin/trips/{id}/pin` 提交 `{"pinned": true}` 或 `{"pinned": false}`
- **THEN** 服务端更新该旅行的置顶状态并返回成功
- **AND** 置顶操作与移除旧置顶在同一事务内完成
- **AND** 非管理员会话调用该接口被拒绝
- **AND** 旅行不存在时返回 404

## Requirement: 公开数据中的置顶标记

- **WHEN** 已解锁访客请求 `GET /api/trips`
- **THEN** 每条已发布旅行对象包含布尔字段 `pinned`，置顶旅行为 `true`，其余为 `false`
- **AND** 公开旅行列表的返回顺序与现有排序规则保持一致

## Requirement: 足迹列表排除置顶旅行

- **WHEN** 已解锁访客打开 `/trips`
- **THEN** 已发布的置顶旅行不出现在旅行卡片列表中
- **AND** 其余已发布旅行保持原有出发日期排序
- **AND** 卡片编号只按当前展示中的旅行从 01 连续计数
- **AND** 排除置顶旅行后没有可展示旅行时，页面显示原有空态提示

## Requirement: 时光轴置顶节点

- **WHEN** 已解锁访客打开 `/timeline` 且存在已发布的置顶旅行
- **THEN** 时光轴最顶部显示该置顶旅行的节点
- **AND** 该节点不显示出发日期与结束日期
- **AND** 节点显示标题、简介与封面缩略图；没有可用封面时沿用渐变占位，点击进入 `/trips/:id`
- **AND** 该置顶旅行不再出现在下方按日期排序的普通节点中

## Requirement: 取消置顶与删除

- **WHEN** 管理员取消置顶，或删除当前置顶旅行
- **THEN** 该旅行回到足迹列表与时光轴中按出发日期排序的位置；删除时直接消失
- **AND** 时光轴顶部不再显示置顶节点
- **AND** 其余旅行的展示顺序不变

## Requirement: 管理端列表完整性

- **WHEN** 管理员查看旅行管理列表
- **THEN** 全部旅行（含草稿与置顶旅行）仍完整显示
- **AND** 置顶状态不改变列表排序
