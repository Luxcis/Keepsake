# 时光轴与旅行足迹展示

## 能力说明

时光轴不再由手工事件维护，而是由已发布旅行足迹自动派生：每个已发布旅行对应一个时间节点，节点按出发日期从近到远推进。公开旅行足迹列表同样以旅行时间为排序依据，最新的旅行在前。管理端不再提供时光轴入口，手工事件表随迁移删除。

时光轴页面仍在门禁之后，沿用现有的门禁提示、空态、错误重试与滚动动效；数据唯一来源为公开旅行列表接口 `/api/trips`。

## Requirement: 时光轴自动生成

- **WHEN** 已解锁访问 `/timeline`
- **THEN** 每个已发布旅行生成一个时光轴节点，节点按 `start_date` 降序排列（最新在前），同一天出发时按 `sort_order` 升序排列
- **AND** 草稿状态的旅行不生成节点
- 验收：A2

## Requirement: 时光轴节点内容

- **WHEN** 时光轴节点渲染
- **THEN** 节点显示出发日期（`end_date` 存在且与 `start_date` 不同时显示为“出发日期 – 结束日期”）、旅行标题、旅行简介和封面缩略图
- **AND** 旅行没有可用封面缩略图时显示现有渐变占位样式
- 验收：A3

## Requirement: 节点跳转

- **WHEN** 点击任意时光轴节点
- **THEN** 进入对应旅行详情页 `/trips/:id`
- 验收：A3

## Requirement: 旅行足迹时间排序

- **WHEN** 已解锁访问 `/trips`
- **THEN** 已发布旅行按 `start_date` 降序排列（最新在前），同一天出发时按 `sort_order` 升序排列
- **AND** 草稿状态的旅行不出现在列表中
- 验收：A4

## Requirement: 管理端移除时光轴

- **WHEN** 访问管理后台
- **THEN** 导航中不再显示「时光轴」标签，`/admin/timeline` 路由不存在并落到页面不存在
- **AND** 管理端不再提供时光轴事件的创建、编辑或删除界面
- 验收：A1

## Requirement: 时光轴接口移除

- **WHEN** 请求 `GET /api/timeline` 或 `/api/admin/timeline` 的创建、更新、删除方法
- **THEN** 服务端返回 404，不再读写手工时光轴事件
- 验收：A1

## Requirement: 手工事件表删除

- **WHEN** 数据库迁移执行
- **THEN** `timeline_events` 表被删除，原有手工时光轴记录不再出现在任何页面或接口
- 验收：A5

## Requirement: 门禁提示

- **WHEN** 未解锁访问 `/timeline`
- **THEN** 页面显示门禁卡片，解锁后自动重新加载时光轴内容
- 验收：A6

## Requirement: 空态提示

- **WHEN** 已解锁但没有已发布旅行
- **THEN** 时光轴页面显示空态提示，文案说明时光轴会在记录旅行后自动出现，不再指引去管理后台补录
- 验收：A6

## Requirement: 加载失败重试

- **WHEN** 旅行列表加载失败
- **THEN** 时光轴页面显示错误信息和重试入口
- 验收：A6
