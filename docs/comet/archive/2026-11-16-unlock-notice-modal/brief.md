# 目标

调整前台解锁时的提示顺序与呈现方式：访客提交口令后先校验口令是否正确，口令错误时提示「访问口令不正确」；口令正确但站点尚未到开放日期时，以弹窗展示未开放提示，而不是把提示文字内联显示在门禁卡片里。站点已开放时，口令正确仍按现有流程解锁。

# 范围

服务端 `POST /api/site/unlock` 调整校验顺序：先执行口令校验（沿用现有按 IP 限速），通过后才判断开放日期。口令错误返回 `gate_mismatch`，口令正确但未开放返回 `not_open_yet` 与渲染后的未开放提示语，且不发放门禁会话。前端门禁卡片 `GatePrompt` 在收到 `not_open_yet` 时弹出未开放提示弹窗，其它错误（口令错误、限速、口令未启用等）仍在卡片内联提示。开放日期判定、提示语文案与 `{date}` 替换规则、门禁 Cookie 与中间件拦截规则均保持不变。

## 目录结构

### 新建

- docs/comet/changes/unlock-notice-modal/specs/site-access/spec.md — 站点访问门禁与解锁流程的完整目标规格。

### 修改

- server/internal/handlers/auth.go — `unlock` 先校验口令与限速，再判断开放日期；更新顺序相关注释。
- server/internal/server/router_test.go — 未开放时错误口令返回 `gate_mismatch`，正确口令仍返回 `not_open_yet` 且带提示语。
- web/src/components/GatePrompt.vue — `not_open_yet` 改为弹窗展示；弹窗关闭后停留门禁卡片，其它错误保持内联提示。

### 明确不建

- 独立的通用弹窗组件或全局弹窗管理 — 该弹窗仅门禁卡片使用一处，内聚在 `GatePrompt` 中即可。
- 新的服务端接口或错误码 — 沿用 `not_open_yet` / `gate_mismatch`，只调整判定顺序。
- 新的站点设置项 — 继续使用 `site_password`、`open_date`、`not_open_message`。

# 非目标

- 不改变开放日期判定规则（Asia/Shanghai 自然日零点）与默认、自定义提示语的渲染方式。
- 不改变门禁 Cookie 的发放条件、有效期、会话实现与中间件拦截规则。
- 不改变管理端「开放日期」「未开放提示语」设置界面与保存逻辑。
- 不改变口令错误、限速、口令未启用等错误的具体文案与限速参数。
- 不提供「口令已验证、开放后自动解锁」之类的免输入能力。
- 不改变首页、旅行、时光轴、生日信、后台等其它页面行为。

# 关键决定

- 口令优先：先校验访问口令，再判断开放日期。这意味着闭站期间也会暴露口令是否正确，并让未开放期间的尝试消耗限速次数；原实现刻意把开放日期判断放在口令校验之前以避免这一泄露，本次按用户明确要求调整并接受该取舍。
- 口令正确但未开放时仍返回 403 `not_open_yet`，响应消息继续使用管理端配置的未开放提示语（`{date}` 替换为中文日期），不发放门禁会话。
- 未开放提示改为弹窗展示，弹窗出现时卡片内不再重复显示同一文案；关闭弹窗后停留门禁卡片，未解锁状态不变。
- 口令错误等失败仍在门禁卡片内联提示，并保留输入框内容以便重试。

# 验收示例

1. 站点已设置未来开放日期时，访客在门禁卡片输入错误口令：卡片内显示「访问口令不正确。」，不出现未开放弹窗。
2. 站点已设置未来开放日期时，访客输入正确口令：出现未开放弹窗，弹窗内提示包含具体开放日期；关闭弹窗后仍停留在门禁卡片，私人内容不可见。
3. 管理端配置了自定义未开放提示语（含 `{date}` 占位符）时，口令正确但未开放的弹窗显示替换日期后的完整自定义文案。
4. 未设置开放日期或开放日期已过时，访客输入正确口令直接解锁并加载页面内容，不出现未开放弹窗。
5. 站点未开放期间，错误口令尝试计入限速；连续失败达到上限后提示「尝试次数过多，请稍后再试」，而不是继续提示口令不正确。

# 验证要求

- 服务端：在 `server/` 执行 `go build ./...` 与 `go test ./...` 通过；覆盖未开放时错误口令返回 `gate_mismatch`、正确口令返回 `not_open_yet` 且带提示语。
- 前端：在 `web/` 执行 `npx vue-tsc --noEmit -p tsconfig.app.json` 与 `npx vite build` 通过；不使用 `npm run build`，避免改写被跟踪的 `tsconfig.app.tsbuildinfo`。
- 弹窗行为：使用隔离的临时数据库与本地 API 预览验证，不直接启动项目真实 `data/` 数据库；验证弹窗出现、文案、关闭后停留门禁卡片以及口令错误的内联提示。
