# 目标

在管理端旅行管理中增加「置顶」能力：同一时刻最多只有一个旅行处于置顶状态。置顶与发布状态相互独立，任意旅行都可以被置顶，但只有已发布的置顶旅行会在前台生效。已发布的置顶旅行不再出现在足迹卡片列表中，而是单独显示在时光轴最顶部，并且该节点不显示日期。

# 范围

置顶是旅行记录上的单值标记，由数据库唯一约束和写入事务共同保证「最多一个置顶旅行」。管理端在旅行列表每行提供置顶开关，编辑表单只读展示当前置顶状态。公开旅行列表接口在已发布旅行上返回置顶标记，前台据此拆分展示：足迹列表排除置顶旅行，时光轴把置顶旅行放在顶部且不显示日期，其余旅行保持原有日期排序。

## 目录结构

### 新建

- server/internal/store/migrations/0007_trip_pinned.sql — 为 `trips` 增加置顶标记列与「最多一个置顶」的局部唯一索引。
- server/internal/store/trip_pin_test.go — 覆盖置顶唯一性、切换置顶、取消置顶与删除置顶旅行。
- docs/comet/changes/pinned-trip/specs/trip-pinning/spec.md — 置顶能力的完整目标规格。
- docs/comet/changes/pinned-trip/specs/timeline/spec.md — 修改后的时光轴与旅行足迹完整目标规格。

### 修改

- server/internal/store/queries.go — `Trip` 增加置顶字段；公开旅行列表与详情查询返回置顶标记。
- server/internal/store/queries_admin.go — 管理端旅行列表返回置顶标记；新增置顶写入方法，在同一事务内清除旧置顶后再设置新置顶。
- server/internal/handlers/admin.go — 新增置顶处理函数，校验入参并复用现有错误映射。
- server/internal/handlers/api.go — 在管理端路由组注册置顶接口。
- web/src/api/client.ts — `Trip` 类型增加 `pinned` 布尔字段。
- web/src/views/admin/AdminTripsView.vue — 旅行列表行内增加「置顶 / 取消置顶」按钮与置顶标识，编辑表单只读展示置顶状态。
- web/src/views/TripsView.vue — 渲染前过滤置顶旅行，卡片编号与空态按过滤后的列表计算。
- web/src/views/TimelineView.vue — 顶部单独渲染无日期的置顶节点，普通节点序列排除置顶旅行。

### 明确不建

- 独立的置顶配置表或站点设置项 — 单值标记放在 trips 行上，唯一性由局部唯一索引与写入事务保证。
- 后台拖拽排序或批量排序界面 — 本次只增加置顶开关，不改变现有 `sort_order` 维护方式。
- 新的公开接口 — 置顶标记随现有 `GET /api/trips` 返回，前台不额外请求。

# 非目标

- 不改变旅行的发布、草稿流程与现有门禁策略。
- 不改变旅行详情页的内容、照片/视频能力与访问方式。
- 不提供多个置顶位或置顶旅行之间的排序。
- 不改变首页随机照片、生日信与后台其他模块。
- 不改变管理端旅行列表的排序规则。

# 关键决定

- 任意旅行可置顶，发布后才在前台生效；草稿被置顶时保留置顶标记，但足迹与时光轴都不展示它。
- 置顶操作入口为旅行列表行内按钮；编辑表单只显示只读的当前置顶状态，不提供第二个开关。
- 时光轴顶部置顶节点只隐藏日期，不加「置顶」标签或其他额外视觉标识。
- 置顶唯一性由 `trips` 上的局部唯一索引保证，写入时在同一事务内先清除原置顶再设置新置顶。
- 取消置顶或删除置顶旅行后，该旅行回到原有日期排序位置，时光轴顶部不再显示置顶节点。

# 验收示例

1. 管理端旅行列表的每一行显示「置顶」或「取消置顶」按钮；点击置顶后该行显示已置顶标识，点击取消置顶后不再有任何旅行处于置顶状态。
2. 置顶新旅行时，原置顶旅行自动取消置顶，列表中始终最多只有一个旅行显示已置顶。
3. 草稿旅行可以被置顶，列表提示「发布后生效」；此时前台足迹列表与时光轴都不展示该旅行。
4. 已发布的置顶旅行不出现在 `/trips` 的足迹卡片列表中，足迹卡片编号只按实际展示的旅行从 01 连续计数。
5. 时光轴最顶部单独显示置顶旅行节点，该节点不显示出发日期与结束日期，仍显示标题、简介与封面并可点击进入旅行详情；该旅行不在下方按日期排序的普通节点中重复出现。
6. 取消置顶后，该旅行回到足迹列表与时光轴中按出发日期排序的位置；置顶旅行改为草稿后，时光轴顶部的置顶节点消失。
7. 删除当前置顶旅行后，页面不报错，时光轴顶部不再显示置顶节点，其余旅行的展示顺序不变。
8. 旅行编辑表单只读显示当前置顶状态，不提供第二个置顶开关。
9. 未登录或非管理员会话调用置顶接口被拒绝；对不存在的旅行调用置顶接口返回 404。

# 验证要求

- 服务端：在 `server/` 执行 `go build ./...` 与 `go test ./...` 通过；新增存储层测试覆盖置顶唯一性、切换置顶、取消置顶与删除置顶旅行。
- 前端：在 `web/` 执行 `npx vue-tsc --noEmit -p tsconfig.app.json` 与 `npx vite build` 通过；不使用 `npm run build`，避免改写被跟踪的 `tsconfig.app.tsbuildinfo`。
- 接口行为：置顶接口位于管理员路由组内，入参只接受布尔 `pinned`；旅行不存在时返回 404。
- 前台行为：足迹列表与时光轴都按 `pinned` 字段拆分置顶旅行；置顶节点的日期元素不渲染，普通节点日期与排序保持现状。
