# 管理端一键备份

## 概述

管理控制台新增「备份」模块。管理员点击一次即可在服务器端生成一个 zip 备份包，包含当前 SQLite 数据库的一致快照、当前存储后端中的全部上传对象以及一份 `manifest.json` 清单。备份包保存在持久卷的 `{BACKUP_DIR}` 目录，管理端可以查看列表、下载和删除；未启用存储时只备份数据库与清单。本能力不包含页面上的恢复/导入，恢复按文档手工执行。

## 需求

### 备份入口与一键备份

管理端导航新增「备份」入口，页面提供一键备份操作。

- 路由为 `/admin/backup`，导航标签为「备份」，沿用现有管理后台布局与鉴权。
- 页面展示备份说明：包含数据库与全部上传文件，不包含 `.env` 与 Redis 数据。
- 点击「立即备份」调用创建接口；创建成功后页面进入生成中状态，按钮禁用，直到任务完成或失败。
- 生成中显示已完成阶段或已处理字节数；页面轮询状态接口刷新进度，完成后自动刷新列表并显示新备份。
- 页面在任务进行中重新进入时，根据状态接口继续显示生成中，不重复触发任务。

Scenario: 一键备份并出现在列表
  WHEN 管理员在「备份」页点击「立即备份」，备份任务成功完成
  THEN 列表出现新条目，显示文件名、大小与创建时间，`{BACKUP_DIR}` 下存在同名备份文件
  验收：A1

### 备份包内容

备份包为 zip，固定包含以下内容：

- 数据库快照：使用配置的 `DB_FILE` 文件名（默认 `journey.db`）位于包根。
- 清单：`manifest.json` 位于包根。
- 上传对象：本地存储时为 `STORAGE_DIR` 下全部普通文件，COS 时为桶内全部对象；包内路径统一为 `uploads/<key>`。
- 不包含 `.env`、Redis 数据、docker-compose、Nginx 配置或备份目录自身。
- 本地枚举跳过 `.upload-*` 上传临时文件、`.DS_Store`、目录、符号链接等非普通文件；`.secret` 正常收录。
- 数据库快照单独可读，不依赖 `-wal`/`-shm` 伴生文件。

Scenario: 解压备份包得到完整数据与文件
  WHEN 管理员下载并解压备份包
  THEN 包内包含数据库、`manifest.json` 与 `uploads/` 下全部上传对象，SQLite 能读出备份前的业务数据，且包内没有 `.env`、Redis 数据或备份目录自身
  验收：A2

### 备份清单

`manifest.json` 描述本次备份内容，便于核对与后续恢复。

- 至少包含：`schema`（固定 `keepsake.backup.v1`）、`created_at`（UTC RFC3339）、`app_env`、`storage_driver`（`local`/`cos`/`none`）。
- `database` 记录包内数据库文件名与字节数。
- `files` 记录包内上传对象前缀 `uploads/`、对象数量与总字节数。
- `objects` 按对象 key 列出每一项的 `key` 与 `bytes`。
- `excludes` 说明未纳入备份的内容（Redis 会话、`.env` 与环境配置、备份目录自身）。
- 清单中的统计与实际包内容一致。

Scenario: 清单与实际内容一致
  WHEN 备份完成后读取包内 `manifest.json`
  THEN schema、创建时间、存储驱动、数据库字节数、对象数量、对象总字节与对象列表同包内实际内容一致
  验收：A3

### 数据库一致性快照

- 数据库快照通过 SQLite 的 `VACUUM INTO` 生成，读取一致事务视图，不直接复制数据库文件或 WAL 伴生文件。
- 快照生成期间服务保持可读写，正常业务写入不因备份失败或长时间阻塞。
- 快照写入备份目录下的临时文件，打包完成后随临时文件一并清理。

Scenario: 备份期间站点可继续写入
  WHEN 备份任务正在生成数据库快照或打包
  THEN 站点仍可新增旅行或照片记录且不报错，备份包中的数据库为一致快照，可单独打开读取
  验收：A4

### 生成状态、并发与失败处理

- 创建接口为异步：接受后返回 202，任务在后台执行，不受原 HTTP 请求取消影响。
- 同一时刻只允许一个备份任务；已有任务运行时再次创建返回 409，页面按钮保持禁用。
- 状态接口返回当前任务（运行中/最近一次结果）与备份列表；最近一次失败保留错误原因供页面展示。
- 生成过程先写临时文件，成功后原子重命名为最终备份文件；任何步骤失败都删除临时文件与临时数据库快照，不发布半成品。
- 服务启动时清理备份目录中的残留临时文件。
- 进程重启会中断进行中的任务；重启后状态接口不再显示该任务，已完成备份不受影响。

Scenario: 失败不残留半成品
  WHEN 备份过程中对象读取失败或写包失败
  THEN 状态接口给出失败原因，列表不出现该备份，备份目录不残留临时文件或半成品压缩包
  验收：A5

Scenario: 并发触发被拒绝
  WHEN 已有备份任务正在生成时再次请求创建备份
  THEN 接口返回 409，页面按钮保持禁用，不会并行生成第二份备份
  验收：A6

### 备份列表、下载与删除

- 列表接口扫描 `{BACKUP_DIR}`，按创建时间倒序返回合法备份文件，包含文件名、字节数与创建时间。
- 下载接口返回 `application/zip`，以附件形式提供，文件名与列表一致；支持大文件读取与断点续传语义（沿用 `http.ServeContent`）。
- 删除接口删除指定备份文件；页面删除前要求确认，删除后刷新列表。
- 备份名称必须匹配 `keepsake-backup-YYYYMMDD-HHMMSS.zip`（冲突时允许 `-<n>` 后缀）；包含 `..`、绝对路径、反斜杠或不符合命名的名称被拒绝，且不得访问备份目录之外的文件。
- 仅管理端页面可操作，下载与删除不对普通门禁会话开放。

Scenario: 下载与删除备份
  WHEN 管理员下载一个备份并随后确认删除它
  THEN 下载得到正确文件名的 zip 附件，删除后列表条目与磁盘文件同时消失
  验收：A7

### 访问控制

- 备份创建、状态/列表、下载、删除全部要求管理员会话，未登录返回 401 `auth_required`。
- 创建与删除沿用现有同源 CSRF 校验；跨站 `Origin` 请求返回 403。
- 备份内容包含密码哈希与私人照片，日志不得输出包内容、对象内容或敏感配置。

Scenario: 未登录与跨站请求被拒绝
  WHEN 未登录请求备份接口，或以跨站 Origin 发起创建/删除
  THEN 未登录请求返回 401 `auth_required`，跨站请求返回 403，且不产生或删除任何备份文件
  验收：A8

### 存储驱动适配

- 本地存储：遍历 `STORAGE_DIR` 收录全部普通文件，包内路径为 `uploads/<相对路径>`。
- COS：分页列出桶内全部对象（处理 `IsTruncated`/`NextMarker`），逐个下载写入包内；空桶时备份成功且文件数为 0。
- 存储未启用（`none`）：只生成数据库与清单，清单文件数量与总字节为 0。
- 任一对象读取失败时整次备份失败，不生成缺少文件的备份包。

Scenario: COS 模式收录全部对象
  WHEN 存储驱动为 `cos` 且桶内存在多个对象
  THEN 备份包逐个收录全部对象，清单 `storage_driver` 为 `cos` 且对象统计与实际一致
  验收：A9

### 构建与检查

- 服务端通过 `go build ./...` 与 `go test ./...`。
- 前端通过 `npx vue-tsc --noEmit -p tsconfig.app.json` 与 `npx vite build`，不使用会改写 `tsconfig.app.tsbuildinfo` 的 `npm run build`。

Scenario: 构建与检查通过
  WHEN 执行服务端构建测试与前端类型检查、构建
  THEN 全部命令通过且不留下被 Git 跟踪文件的意外修改
  验收：A10

### 配置与文档

- `BACKUP_DIR` 可覆盖备份目录，默认 `{DATA_DIR}/backups`；`.env.example` 与 docker-compose 提供对应说明和默认值。
- README 记录备份位置、包内容、排除项与手工恢复步骤（停止服务、解压覆盖数据库与上传目录、启动服务）。
- 不把备份包上传到任何外部服务。

Scenario: 配置与恢复文档可用
  WHEN 运维按 README 与 `.env.example` 配置并执行恢复步骤
  THEN 能定位默认备份目录、理解包内容与排除项，并按步骤恢复数据库与上传文件
  验收：A11
